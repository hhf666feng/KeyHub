# KeyHub 使用指南

[产品介绍](../README.zh-CN.md) · [English](guide.md) · [安全说明](../SECURITY.zh-CN.md)

本文记录 KeyHub `0.16.1` 的操作与兼容性约定。

## 密码库与编辑

个人保险库支持登录、信用卡、身份资料、安全笔记、SSH、API 和自定义项目，并提供类型筛选、文件夹与收藏。字段仍可自由组合；账号、密码、卡号、安全码、身份地址和安全笔记均作为加密字段保存。公开用途、名称和文件夹属于项目元数据。

浏览器插件支持登录密码与 Passkey，以及信用卡、身份资料的新增、编辑和手动填写，修改直接写入同一个本地密码库。支持标准 HTML `autocomplete`、常见字段名与标签、月份控件、到期年月格式和下拉选项；跳过隐藏、透明、禁用和只读控件。聚焦相关表单时只填写该表单。只在 HTTPS 网站（或本机测试地址）上执行，不自动提交表单，也不跨来源填写 iframe。完整卡号和安全码不会出现在列表中。复杂支付组件、第三方支付 iframe 和非标准字段仍可能需要手动填写。

桌面端与插件均有密码生成器，可选 8–128 位、大写、小写、数字与符号，使用系统安全随机数；不会保存生成历史。

插件的「完整密码库」在浏览器管理页和普通网站上都可使用，支持搜索、类型筛选、文件夹、收藏、登录网址与匹配规则，以及信用卡、身份和笔记编辑。删除项目会先移入「回收站」，保留到你恢复或永久删除；回收站项目不能填写密码或签署 Passkey 登录。恢复时如有同名项目，会自动改名，避免覆盖。

修改已保存的密码会加密保留最近 20 条旧密码。桌面端与插件解锁后可以查看、复制或清除「密码历史」；Agent 和自动填写无法请求旧密码。完整备份同时包含回收站和密码历史。永久删除或清除历史不会修改已有备份中的旧副本。

KeyHub 没有自有账号、订阅、托管密码库或远程 MCP 服务。它免费开源，支持 Windows、macOS 和 Linux，保险库在当前设备本地加密保存。可选的 GitHub 备份将加密快照保存到用户自己的私有仓库。本地 `stdio` MCP 只在 Agent 调用时启动。

## 每个模块独立控制明文

每个模块都有自己的 Agent 可见性开关：

- **隐藏** — 凭据模块的默认状态。KeyHub 可以使用该值，但 MCP 返回中不会包含它。
- **可见** — 只有用户明确打开开关后，该值才允许返回给 Agent。
- **TOTP** — KeyHub 只生成当前六位验证码，永久种子不会返回。

编辑器中的查看与复制按钮供本机用户使用。可选六位 PIN 保护 GUI 明文查看和扩展密码库访问，并为每次 Passkey 操作提供身份验证；它不代替保险库加密，也不会关闭 MCP 动作。

模块通过左侧拖动把手调整顺序，也可以聚焦把手后使用上、下方向键。输入框内可以正常输入、选择和复制文字。删除项目、模块或草稿前会显示确认；模块删除在保存项目后生效。

## 批量添加环境变量

在新建凭据的“从一个组合开始”中选择 **环境变量**，或在编辑器中打开 **添加模块 → 环境变量组**，每行粘贴一个 `KEY=VALUE`。支持空行、`#` 整行注释、`export KEY=VALUE` 和成对引号，也可以粘贴值中包含的 `=`。KeyHub 会一次生成多个自定义字段；生成后的 KEY 名仍可单独修改。非法名称、重复 KEY 或与内置字段冲突时，整批内容不会被部分添加。值保持“隐藏”时仍可由 MCP 的 `secretEnv` 或 `{{keyhub:KEY}}` 占位符在本地注入，不需要向 Agent 返回明文。

## 浏览器、SSH 与 API

### 浏览器填写

随包提供的 Chromium 扩展与桌面软件共用同一份本地加密密码库。打开 **设置 → Browser Bridge**，按编号完成两步：**1. 打开扩展页**，并开启右上角的“开发者模式”；**2. 拖入插件**，将 KeyHub 标识拖到扩展页空白区域后松开。如果无法自动打开页面，请在 Chrome 地址栏输入 `chrome://extensions`。“拖拽无法安装？”中保留了扩展目录按钮，可配合“加载已解压的扩展程序”手动安装。安装后保留 `browser-extension` 文件夹，扩展会自动配对。固定扩展 ID 与已有配对不因改名而变化；替换扩展文件后重新加载即可。移除安装或重置配对后才需重新配对，不必仅为显示名称变化重新配对。

点击浏览器工具栏的 KeyHub 图标，可选择当前网站的账号并填写用户名与密码。未设置专门规则时，匹配协议、主机和端口。桌面项目编辑器支持多个网站，以及同源、主域名、主机、完整网址、前缀、正则和“不匹配”规则；填写会校验实际目标 frame 的完整地址，并在写入前再次核对。不会自动提交表单。点击“保存当前网站的账号”读取页面表单，再确认新建或更新本地项目；扩展和桌面端会刷新同一份数据，并阻止覆盖已发生变化的项目。配置 PIN 后，扩展需要解锁，解锁会话有效期为五分钟。软件及 Browser Bridge 需要保持运行。

自动保存提示默认关闭。在插件弹窗开启「登录或注册后提示保存」后，提交登录、注册或修改密码表单时会显示「预览保存」提示和工具栏 `+` 标记。自动识别账号及新密码，排除隐藏字段、验证码和支付字段；密码不一致或无法明确选择时不自动生成建议。在扩展窗口中核对来源网站和内容，必要时先解锁，再确认新建或更新已有账号。提交表单不代表登录或注册成功；密码库解锁时，未变化的已有账号不会重复提示。待保存信息只保留在插件后台内存中，最长五分钟；忽略、在插件中主动锁定、连接断开、关闭标签页或跳转到其他来源时清除。关闭此选项会停止采集并清除待保存建议。

支持 HTTPS／本机测试网页的标准表单提交、可识别的登录或注册按钮、回车提交、动态表单、开放的 Shadow DOM 和同源 frame。「下一步／继续」提交的用户名可在同一标签页、frame 和来源的后续密码步骤中使用，仅保留在内存中，最长两分钟；锁定、断开连接或关闭保存提示时同样清除。密码填写会触发 input/change 事件，兼容 React 受控输入框和 Vue 模型。封闭的 Shadow DOM、跨来源分步登录、含糊字段和没有可识别标签的自定义按钮，仍可能需要手动填写或「保存当前网站的账号」。

网站发起 Passkey 创建或登录时，KeyHub 会打开独立确认窗口。创建的 Passkey 作为独立项目保存在本地密码库，私钥始终在桌面端加密保存，扩展只接收注册结果和登录签名。要求身份验证的网站需要先在 KeyHub 设置六位 PIN，每次 Passkey 请求都重新验证 PIN。可在确认窗口选择“使用设备或安全密钥”返回浏览器原生流程。桌面项目编辑器显示 Passkey 的网站与账号；移入回收站后停用，恢复后可继续使用，永久删除才会移除本机凭据。

当前 Passkey 支持 HTTPS 顶层页面及本机 `localhost`、ES256、可发现凭据和指定凭据登录。跨域 iframe、条件式自动填充、硬件认证证明及高级 WebAuthn 扩展不由此版本接管；不兼容的请求应使用设备原生流程。现有其他提供方的 Passkey 不会自动迁入。

Agent 的 `credential_fill` 仍把一个选定字段写入聚焦控件；显式设置 `submit=true` 时可提交所属表单。该路径不执行上述网站账号匹配，也不导出 Cookie。

### SSH

KeyHub 支持密码与私钥认证、不限制长度的命令与输出、直接传入标准输入，以及递归 SFTP 上传/下载。主机、端口和账号既可保存为默认值，也可在当前任务中临时提供。目标父目录会自动创建，已有文件或目录只会在完整临时副本准备好后替换。KeyHub 不固定或比较 SSH 服务器指纹，认证明文不会返回给 Agent。

### HTTP API

KeyHub 会识别常见 API 服务与 Basic 认证组合，无法识别时使用 Bearer Token。保存的服务 URL 只是默认地址和相对路径基准，不是 Origin 限制；Agent 可按任务使用任意 HTTP/HTTPS 目标。其他协议可在 URL、Header、Query、JSON/文本正文或表单中写 `{{keyhub:模块名}}`，由 KeyHub 在本地解析。重定向会正常跟随，响应默认没有大小上限，也可直接流式保存到本地文件，并支持 multipart 文件上传。

## 本地程序设置

macOS 上点击屏幕顶部的 KeyHub 图标可打开快捷面板：搜索凭据名称、查看
Agent 接入和最近活动、打开完整窗口、锁定或退出。点击其他位置或按 Esc
收起。面板只显示元数据；已配置 PIN 且处于锁定状态时不返回凭据和活动列表。

**设置与接入 → 窗口与锁定 → 仅在菜单栏运行** 可隐藏 Dock 图标，并在
下次启动时保持主窗口收起。面板中的“完整窗口”和 Finder 中重新打开应用
仍可恢复全部功能。关闭该选项可恢复 Dock 显示；如果托盘初始化失败，
主窗口与 Dock 入口仍会保留。设置里还提供“打开快捷面板”预览入口。

设置页包含：

- 创建桌面快捷方式（受支持的平台）与开机自启动；
- 关闭到托盘或真正退出；
- 可选六位本地 PIN；
- Agent 接入、扫描与修复；
- Browser Bridge 配对；
- 可选的 GitHub 私有仓库加密备份与换机恢复；
- 加密备份导入、导出与打开本地数据目录。

替换或升级可执行文件不会删除保险库。KeyHub 会继续读取当前系统用户的数据目录：

| 平台 | 保险库位置 |
| --- | --- |
| Windows | `%APPDATA%\mcp-vault\v2` |
| macOS | `~/Library/Application Support/mcp-vault/v2` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/mcp-vault/v2` |

桌面端导出的 `.mvault` 使用独立备份密码（至少 12 个字符），通过 Argon2id（64 MiB、3 次、1 并行）派生密钥，再用 XChaCha20-Poly1305 加密完整备份；文件内不包含解锁密钥。恢复时需要原密码。旧版和现有 CLI 自动解锁包仍可导入，其文件包含解锁材料，须像原始凭据一样保护。

## 迁移与兼容性

[改名兼容表与 Agent 修复步骤](../README.zh-CN.md#迁移与能力保持)。

兼容标识不是显示品牌：应用 ID `dev.kru.desktop`、本地秘密 AAD `mcp-vault/secret/v2`、便携格式 `mcp-vault-portable` 及现有 `kru/backup/v3` 至 `kru/backup/v8` 版本化 AAD 均保留。GitHub 快照继续使用文件名 `openkeylet.vault.json`、格式 `openkeylet-cloud-backup` 和 AAD `openkeylet/cloud-backup/v1`；本机 GitHub 设备状态格式仍为 `openkeylet-github-device`。完整容器标识见[安全说明](../SECURITY.zh-CN.md#本地数据与备份)。

macOS 当前使用数据目录中的应用私有 `master.key`，目录权限为 `0700`，密钥文件为 `0600`。已有密码库缺少文件密钥时，启动只尝试不弹窗读取旧 Keychain 条目 `mcp-vault` / `master-key-v2` 并迁入文件；失败后拒绝创建替代密钥，避免覆盖原数据。需要明确授权旧钥匙串访问时，可使用本机构建的可执行文件运行：

```sh
/Applications/KeyHub.app/Contents/MacOS/keyhub key migrate
```

该命令可能触发系统授权；路径须对应实际安装位置。Windows／Linux 优先使用系统凭据存储（同一服务／账号），不可用时使用本地权限保护的密钥文件。PIN 不是主密钥。不要删除 `master.key` 来排障，也不要把数据目录或自解锁备份当作可公开的加密文件。

## GitHub 加密备份

在 **设置 → GitHub 加密备份** 中连接自己的私有仓库：

1. 点击“设置 GitHub 备份”，选择授权方式。已通过 [GitHub CLI 登录](https://cli.github.com/manual/gh_auth_login)的用户可复用本机授权；也可填写自己的 [GitHub 细粒度访问令牌](https://github.com/settings/personal-access-tokens/new)。仅安装 Git 不代表已登录 GitHub。
2. 点击“检查账号”，确认实际授权账号，再填写 `owner/repository`。连接已有私有仓库时，令牌仅需选择该仓库并授予 **Contents: Read and write**。
3. 没有仓库时，可勾选“由 KeyHub 在我的账号下创建此私有仓库”。需要具备创建仓库的授权（细粒度令牌还需 **Administration: Write**）；组织仓库请先在 GitHub 网页创建。已有同名仓库不会被接管或修改可见性，取消此选项即可按现有仓库连接。
4. 选择“创建新备份”，生成恢复密钥，在仓库之外保管并勾选确认。保留“立即上传第一份加密备份”时，按钮为“连接并上传”；取消勾选则只保存连接，之后再点“立即备份”。
5. 换机时选择“连接已有备份”，填写同一仓库、原恢复密钥及授权，再点击“从云端恢复”。恢复前会禁止上传，避免覆盖已有备份。

GitHub CLI 授权只在你检查账号或提交连接时读取，不会把令牌返回界面或写入日志；连接成功后按现有方式加密保存在本机。首次上传失败会保留连接并显示错误，可以按提示重试，不必重新创建仓库。创建仓库结果不确定时，先在 GitHub 检查，再决定是否连接现有仓库。

完整的便携数据（包括项目名、地址、备注和凭据）在本地使用 XChaCha20-Poly1305 和独立随机生成的 256 位恢复密钥加密。GitHub 只接收 `openkeylet.vault.json`，其中没有解锁密钥。令牌与恢复密钥由当前设备的保险库主密钥加密保存，不包含在备份里。浏览器配对、PIN、Agent 接入配置、操作记录和草稿仍保留在各自设备；已解锁 GUI 可以查看保存的恢复密钥。

快照加密保护机密性与完整性，不保证远端可用性，也不提供密码学防回滚能力。仓库所有者之后仍可能公开或删除仓库；持有恢复密钥及任意快照的人可以解密该快照。

第一版提供**手动快照备份与合并恢复**，不自动进行双向同步。恢复时跳过相同项目，将同名但内容不同的项目另存，不覆盖或删除本机项目。新连接的设备必须先恢复已有快照才能上传；远端版本发生变化或存在并发写入时会停止上传。每次上传和恢复都会检查仓库仍为私有。当前支持 GitHub.com 仓库，加密快照最大为 8 MiB。

恢复密钥丢失且没有仍连接的设备时，云端备份无法找回。Git 历史会保留旧版密文，包括已删除凭据；“断开”仅移除本机连接，不删除仓库历史或撤销 GitHub 令牌。旧版和 CLI 自解锁 `.mvault` 包不能直接作为安全的云同步密文上传。

## 格式版本与其他密码库导入

新备份内部数据为 v8，包含项目类型、文件夹、收藏、网站匹配规则、Passkey、密码历史和回收站，仍可导入原有 v3/v4/v5/v6/v7 备份。现有 v7/v8/v9/v10/v11 保险库可直接读取，首次修改时保存为 v12。旧版程序不能读取 v12 保险库、新版密码保护容器或 v8 备份内容。

在 **系统 → 本地数据 → 迁入密码库** 中选择 Bitwarden 未加密 JSON，或 Chrome/Edge 密码 CSV。先预览项目数量及兼容性提示，再确认导入。取消不会改变密码库；确认后整批原子合并，相同项目去重，不覆盖已有项目。选中的文件只读取一次，待确认数据在内存中加密保存，五分钟后过期。

Bitwarden 导入保留登录、信用卡、身份、安全笔记、SSH 密钥、文件夹、收藏、备注、自定义字段和多网址规则。支持迁入 ES256/P-256 PKCS#8 Passkey，保留凭据 ID、用户标识与计数；旧版非零计数在返回登录签名前于密码库锁内更新，迁移后应避免继续使用这些凭据的另一副本。支持 Base32 和 `otpauth://totp`、SHA-1/SHA-256/SHA-512、6–8 位验证码及可配置周期；不支持的验证码密钥原样保留，并在预览中提示。

预览会说明尚未兼容的差异：附件需单独转移；关联字段以加密自定义字段保留；最近 20 条旧密码进入密码历史，更长的历史会同时归档到加密自定义字段中。逐项主密码验证和组织共享权限不会迁移。原回收站项目会跳过。不支持的项目类型、无效密钥或错误记录会使整次导入失败，不产生部分写入。原导出文件不会被修改或删除。

## MCP 调用约定

KeyHub 提供下表全部 12 个 MCP 工具，直接使用唯一项目名，不要求 Agent 提供内部项目 UUID。用户已经说出项目名且动作明确时，Agent 可以直接执行；显式使用项目或让 `items_search` 唯一命中后，它会成为当前 MCP 会话的轻量上下文，后续兼容的填写、SSH、传输、HTTP 和终端动作无需重复项目名。KeyHub 也能理解 `使用 KeyHub MCP 中的「生产服务器」` 这类自然表达。只有发现、切换、查看模块或消除歧义时才需要搜索。

绝不能要求用户提供隐藏的明文；未知字段和已停用的工具名会被拒绝。

每个 Agent 会话拥有自己的 stdio MCP 进程。启动新版 KeyHub 或另一个 Agent 会话不会中断已经进行中的任务；只有客户端结束会话，或用户从 KeyHub 托盘明确选择退出时，相关 MCP 进程才会结束。

安装更新后的二进制后，启动新的 Agent／客户端会话才能发现 `items_create`；桌面程序更新不会让现有 stdio 进程自动获得新工具。本指南不代表已安装更新后的程序，也不代表客户端已加载它。

| 工具 | 用途 | MCP 影响提示 |
| --- | --- | --- |
| `items_search(query?)` | 查找已启用的项目（含未补全的骨架）、模块和自动开放的动作 | 只读、幂等、本地 |
| `items_create` | 创建秘密字段留空且隐藏的骨架，可附公开目标地址 | 修改本地密码库；同名拒绝，不覆盖 |
| `credential_fill` | 在当前聚焦的本地目标中使用一个保存的模块，可选择同时提交 | 改变本地状态；提交可能产生外部影响 |
| `terminal_run` | 一步运行本地 shell 命令，可传入标准输入并替换隐藏模块 | 可能产生本地或外部影响 |
| `ssh_run` | 使用已保存身份及保存或临时提供的 SSH 目标执行命令 | 可能产生外部影响 |
| `ssh_upload` | 使用已保存身份递归上传本地文件或目录 | 读取本地路径并改变远端目标 |
| `ssh_download` | 使用已保存身份递归下载远端文件或目录 | 读取远端路径并改变本地目标 |
| `http_send` | 发送认证 HTTP 请求，可选择传输本地文件 | 可能产生外部及本地文件影响 |
| `terminal_start` | 启动托管本地进程 | 改变本地状态 |
| `terminal_write` | 向托管终端写入普通输入 | 可能产生外部影响 |
| `terminal_read` | 读取已脱敏的托管终端输出 | 只读、幂等、本地 |
| `terminal_stop` | 关闭托管终端会话 | 幂等状态变更 |

KeyHub 不提供不受限制的 `get_secret`。`items_search` 只返回项目与模块元数据、非秘密目标信息和自动推导的动作。只有用户明确打开 Agent 可见开关的凭据值才会出现在返回中；未知参数和已停用的旧工具名会被拒绝。

普通命令、脚本、JSON 或配置可直接通过 `terminal_run.stdin` 或 `ssh_run.stdin` 传入，无需 shell 转义或临时文件。命令、标准输入、路径、PTY 输入和 HTTP 请求字段都可用 `{{keyhub:模块名}}` 引用隐藏模块。本地路径支持绝对路径、`~/...` 和相对 MCP 启动工作区的路径。KeyHub 不再对命令长度、SSH/终端输出、模块数量或并发终端数量设置固定上限；调用方仍可主动设置超时或响应大小限制。

每次成功的工具调用都会返回带类型的 `structuredContent` 及等价的 JSON 文本。业务失败返回带 `isError=true` 的 MCP 工具结果；格式错误的协议输入仍属于协议错误。工具注解帮助客户端说明影响，但实际安全限制全部由 KeyHub 后端执行。

### 创建凭据骨架

`items_create` 用于准备字段，不用于导入或披露秘密。参数如下：

| 字段 | 约定 |
| --- | --- |
| `name` | 必填，唯一项目名 |
| `description`、`folder`、`itemType` | 可选的公开元数据，不能放秘密。项目类型支持 `login`、`card`、`identity`、`secureNote`、`ssh`、`api`、`custom`；省略时由校验器推导 |
| `modules` | 必填模块对象数组；对象含 `kind`，`customSecret` 可带 `name`，只有公开的 `host`、`port`、`url` 目标可带 `value`；`customSecret` 必须提供合法且唯一的字段名 |

核心模块类型为 `username`、`password`、`apiCredential`、`privateKey`、`passphrase`、`totp`、`customSecret`、`host`、`port`、`url`。现有校验器支持的银行卡、身份及 `secureNote` 个人字段类型也可用于建骨架。包括用户名在内，所有凭据及个人字段都必须留空，由所有者补全；只有公开目标类型可以携带 `value`。秘密字段直接省略 `value`。不能用该工具创建 Passkey，应通过浏览器支持的注册流程创建。

不接受 `id`、更新／删除操作、`agentVisible` 覆盖或调用方控制的启用标志。秘密字段强制隐藏，新项目设为启用。校验与唯一名称创建是原子操作：同名会失败，不覆盖、不更新，也不产生部分项目。已启用不等于空秘密已经可用。

以 ASR 服务为例，调用 `items_create` 时传入：

```json
{
  "name": "ASR API",
  "description": "Speech-to-text service",
  "folder": "AI services",
  "itemType": "api",
  "modules": [
    { "kind": "url", "value": "https://asr.example.com" },
    { "kind": "apiCredential" }
  ]
}
```

示例 URL 仅用于说明，不代表已验证的服务。成功响应包含 `created: true`、`item: {name, modules, actions}`、`requiresOwnerInput`、`missingFields` 和 `nextStep`。每个模块返回 `{kind, name, configured, agentVisible, value?}`；可包含公开目标值，但不返回隐藏秘密。此例中，留空的 `apiCredential` 未配置且隐藏，`actions` 为 `[]`，`requiresOwnerInput` 为 `true`；`missingFields` 和 `nextStep` 指明所有者需要补全的内容。

所有者在 KeyHub GUI 打开 **ASR API**，如配置了 PIN 则先解锁所有者界面，在本地填写 API 凭据，保持 Agent 可见关闭并保存。随后 Agent 再次搜索该项目，使用开放的 `http_send` 动作，无需获得 Token。配置可用凭据前，`items_search` 仍返回已启用骨架及 `actions: []`；已禁用项目仍被排除。能搜索到项目或返回 `created: true` 不代表 API 可达或认证成功。

所有者 PIN 不阻止 MCP 动作：创建骨架是本地密码库写入，不是访问 GUI 所有者专用的秘密查看／填写控件。不要让所有者把 Token 粘贴进对话，也不要将其作为 `items_create` 参数发送。详见[安全边界](../SECURITY.zh-CN.md#凭据骨架创建)。

## 开发与验证

`npm run test:unit` 执行离线 Node 单元／契约检查；`npm run test:ui` 串行执行
合成界面测试，默认使用 Playwright Chromium，可通过 `PLAYWRIGHT_CHANNEL=chrome`
选择已安装的 Chrome（适用的测试支持该覆盖）。`npm run lint` 检查 JavaScript
语法与版本一致性，不是 JavaScript 语义类型检查；Rust 类型和 lint 由 Cargo check
与 Clippy 检查。

浏览器集成测试使用独立 Chromium 配置加载真实扩展，并创建仅含测试凭据的临时密码库。安装 Playwright Chromium（`npx playwright install chromium`）后，运行 `npm run test:browser`。请按环境存储要求配置 `PLAYWRIGHT_BROWSERS_PATH`、`CARGO_TARGET_DIR` 和临时目录。测试覆盖密码同步、独立验证的 Passkey 注册与签名，以及取消流程；从桌面拖入 Chrome 的原生拖拽仍需手动检查。

登录兼容性测试入口：`npm run test:login-patterns -- --all-browsers` 覆盖 Chromium 和已安装的 Chrome、Edge；`npm run test:login-flows` 使用真实扩展、React/Vue 组件、动态表单和分步登录；`npm run test:login-capture` 检查保存确认、密码历史、隐私和来源隔离。可选的 `npm run test:public-logins` 只读取 GitHub、Google、微软、GitLab 公开登录页的字段结构，不输入账号、不提交表单。结构检查或模拟流程通过不代表真实网站认证已通过；验证挑战及无法访问的页面会标记为未验证。

常用构建、单元测试与静态检查入口见 [README](../README.zh-CN.md#开发与构建)。`test:ui` 使用 Playwright，需要先安装 Chromium。原生菜单栏焦点、拖拽安装、操作系统授权及签名／公证仍需在目标平台验证；模拟界面或打包夹具通过不能代替这些检查。
